# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor, etc.) working in this repository.

## What this is

The **GMU CS Directory**: a static Vite site listing George Mason University Computer Science
faculty and staff (`index.html`, `public/faculty.json`), graduate students and alumni
(`students.html`, `public/students.json`), and honors (`?view=awards`, `public/awards.json`), sourced faculty/student news
(`news.html`, `public/news.json`), plus
one static profile page per person (`people/<slug>.html`, generated by
`scripts/generate-profile-pages.ts`). Deployed to GitHub Pages from `main`
(<https://realgmucs.github.io/people/>).

## Commands

```bash
npm run dev          # Vite dev server (regenerates profile pages first)
npm test             # unit and data-contract tests (tests/*.test.ts)
npm run typecheck
npm run validate:data
npm run build        # typecheck + validate:data + tests + Vite build + profile pages
npm run news:sources -- --limit 10  # next faculty homepage/lab sources to review for news
npm run news:watch -- --report r.json  # new text on every faculty site and CV since the snapshot
npm run news:feeds -- --report f.json  # new NSF awards, CEC grants-list entries, and flagship-venue papers
npm run next-batch -- <check|honors|discover|portraits>   # next batch for a scheduled routine
npm run fetch:portraits -- --name "Full Name"            # localize a faculty Picture URL
npm run sync:vietprofs-ui   # re-copy the shared UI from ../vietprofs
```

For data-only edits, `npm run build && git diff --check` is the full check.

## Roster data

Read [ROSTER_MAINTENANCE.md](ROSTER_MAINTENANCE.md) before researching or editing any record: it
is authoritative for inclusion, field formats, sources, timestamps, and the `Verified` marker.
Key rules:

- Every changed record gets `Last Modified`; every record checked against a live source gets
  `Last Verified` (both `YYYY-MM-DD`).
- `Verified: Yes` only for facts confirmed by direct correspondence with the person, their
  advisor, or the department. Never set it from web research.
- Unknown beats wrong: leave a field blank rather than guess a year, a job, or a link from a
  name-only match.
- Keep the JSON files' 4-space formatting and key order; `tests/data-contract.test.ts` checks them.
- `Advisor` / `Co-Advisor` must match a faculty record's `First Name Last Name` exactly, so the
  faculty card can link its students.

**Direct updates.** Information the owner (`nguyenthanhvuh`) supplies, in a conversation or in an
Issue that relays what a faculty member, student, or the department said, is ground truth: apply
every field it asserts and set `Verified: Yes` on the records it confirms. Automated work never
overrides a `Verified: Yes` record with web evidence; a conflict goes in an Issue for the owner.

## Repository workflow

- Owner-directed local sessions may commit straight to `main` (a push redeploys the site in about
  a minute). Verify every fact against its source before pushing.
- **Scheduled cloud routines** follow [TASKS/AUTOMATION.md](TASKS/AUTOMATION.md) instead: producers
  open `[scheduled:<key>]` PRs and Issues and never push to `main`; the weekly auditor reviews and
  merges them. Before reviewing, merging, or closing a PR or Issue, read
  [TASKS/AUDIT_ISSUES_PRS.md](TASKS/AUDIT_ISSUES_PRS.md).
- Task playbooks for each kind of maintenance are in [TASKS/](TASKS/README.md).

## Shared UI

The look and search behavior come from VietProfs (`../vietprofs`). `src/vietprofs/` holds
verbatim, hash-checked copies of its `roars-ui.css`, `search-kit.ts`, and `back-to-top.ts`; never
edit them here. Change them in VietProfs, then run `npm run sync:vietprofs-ui`. `src/style.css`
imports `roars-ui.css` first and holds only this site's layout and components.
